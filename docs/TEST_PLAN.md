## Цели и задачи

Проверить, правильно ли считаются площадь и периметр у четырёх фигур.  
Найти ошибки, если они есть, и зафиксировать результат.

## Что тестируем

Библиотека `geometric_lib`: модули `circle`, `square`, `rectangle`, `triangle`.  
У каждой фигуры функции `area` и `perimeter`.

## Область тестирования

| Модуль | Функции |
|--------|---------|
| circle.py | area(r), perimeter(r) |
| square.py | area(a), perimeter(a) |
| rectangle.py | area(a, b), perimeter(a, b) |
| triangle.py | area(a, b, c), perimeter(a, b, c) |

## Стратегия

- unit-тесты на `unittest`
- сравниваем результат с ручным расчётом по формулам
- смотрим обычные значения и нули
- для треугольника площадь ожидаем по формуле Герона (три стороны)

## Критерии приёмки

- тесты запускаются командой `python -m unittest`
- покрыты все 4 фигуры
- по каждому падению есть вывод в отчёте

## Ожидаемые результаты

Часть тестов может упасть — это тоже результат.  
Так мы находим баги в готовом коде.

## Актуальные результаты

Запуск из корня `geometric_lib`:

```bash
python -m unittest discover tests -v
```

Итог: **17 тестов, 3 падения**.

- круг — все ок
- квадрат — все ок
- прямоугольник — площадь ок; периметр падает (`15 != 30`, `7 != 14`)
- треугольник — периметр ок; `area(5,5,6)` падает (`8 != 12`)  
  у `3-4-5` значения Герона и `(a+b+c)/2` случайно совпали (=6), поэтому один тест площади прошёл

## Выводы

Нашлись ошибки в готовом коде:

1. `rectangle.perimeter` считает `a+b` вместо `2*(a+b)`
2. `triangle.area` считает полупериметр `(a+b+c)/2` вместо площади по Герону

Код фигур не меняли. Проваленные тесты как раз показывают баги.
